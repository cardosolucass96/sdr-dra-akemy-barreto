# Development Agent Context

This repository is the LangGraph-based SDR template integrated with Pipefacil.

Before changing LangChain, LangGraph, LangSmith, Langfuse, MCP, prompts, chains, nodes,
tools, checkpointers, or agent runtime behavior, consult the current official docs:

- Documentation index: https://docs.langchain.com/llms.txt
- LangChain docs MCP server: https://docs.langchain.com/mcp
- Langfuse documentation index: https://langfuse.com/llms.txt
- Langfuse docs MCP server: https://langfuse.com/api/mcp

Prefer the MCP server when the current AI/client supports MCP. Use the documentation index
to discover relevant pages before relying on memory.

Development-only rule:

- MCP documentation connectors and AI assistant settings are for local development only.
- Do not import MCP docs clients in production code.
- Do not add docs/MCP assistant tooling to runtime dependencies.
- Do not require these tools in the Docker image or production startup path.

Core boundary:

- `api` validates HTTP and delegates to `application`.
- `application` orchestrates use cases.
- `agent` owns LangGraph state, graph, routing, nodes, chains, prompts, and tools.
- `integrations` owns external API contracts, mapping, and HTTP clients.
- `observability` owns Langfuse clients, tracing helpers, prompt fetching, fallback behavior,
  and masking.

Derived SDR design:

- The graph in this repository is a smoke-test scaffold, not the intended complete commercial
  flow. When deriving an SDR, model its actual business decisions, data lookups, actions,
  retries, checkpoints, and independently testable responsibilities as small, named nodes.
- A node reads state, performs one cohesive responsibility, and returns a partial state update.
  Do not create a node for a trivial field mapping; do not hide several business decisions,
  Pipefacil calls, and the final reply in one `resolve_conversation` node.
- Use LLM inference with native structured output for conversational meaning that affects
  state, routing, qualification, handoff, or actions: intent, acts, facts, corrections,
  questions, objections, refusal, and confidence. Validate the schema before routing.
- Do not infer conversational meaning by parsing model prose, `json.loads` on model prose,
  regex, keyword lists, or string containment. Parsing and regex are reserved for formal,
  deterministic formats such as transport payloads, IDs, dates, commands, and contract
  validation.
- Keep routing pure and deterministic over the validated state. Before changing a derived
  agent, read `docs/derivacao-agente.md` with the architecture and conversational-modeling
  guides, then identify the state fields, node responsibilities, and graph edges required.
- A commercially meaningful local change that projects to Pipefacil (lead fields, tags, owner,
  status, deal stage, handoff, or equivalent) must create a durable Pipefacil-sync operation in
  the same state update. Route immediately to a dedicated Pipefacil action node; never postpone these
  updates until a later stage change or the end of a conversation.
- Pipefacil sync must be idempotent, record a receipt on success, and retain the pending operation
  plus failure information on error. A derived agent that requires sync even when a chat stops
  must use a durable outbox and retry worker; the base has neither distributed retries nor a
  queue.

Deterministic quality gate:

- Before completing code changes, run `make quality` from the repository root.
- The gate applies the architecture and agent contracts documented in
  `docs/quality-gates.md` to every change, regardless of whether it was generated by AI.
- Do not weaken thresholds, add exclusions/suppressions, skip required tests, or change the
  comparison base to make the gate pass unless the user explicitly requests that policy change.
